# Dota 2 · Прогноз победы Radiant

Учебный ML-проект по курсу «Машинное обучение» ФКН ВШЭ. Задача — по составам команд, чатам и событиям первых 15 минут оценить вероятность победы Radiant. Во всех основных экспериментах используется логистическая регрессия. Меняются признаки, предобработка и регуляризация.

## Что в проекте

| Материал | Содержание |
| --- | --- |
| [Базовый ноутбук](notebooks/homework-practice-03-base.ipynb) | Разведочный анализ, OHE региона и дня недели, обработка MMR, очистка составов и разреженное кодирование героев, подбор параметров через Optuna |
| [Продвинутый ноутбук](notebooks/homework-practice-03-advanced.ipynb) | TF-IDF чатов обеих команд, агрегации золота и опыта, тренды и временные окна, новые признаки, жадный отбор групп, формирование сабмита |
| [Эксперимент CPU / GPU](scripts/kaggle_gpu_benchmark_cell.py) | Отдельная ячейка для Kaggle. Сравнивает sklearn и cuML на одних и тех же разреженных матрицах |
| [Скрипт запуска](scripts/run_notebooks.py) | Последовательно выполняет оба ноутбука в одной рабочей папке и сохраняет копии с результатами |

## Результаты

Качество измеряется как `Gini = 2 × ROC AUC − 1`. Для проверки используются временные разбиения. Модель обучается на ранних матчах и оценивается на более поздних.

| Конфигурация | Gini на CV из пяти временных фолдов |
| --- | ---: |
| Метаданные матча и MMR | 0.14797 |
| + составы героев | 0.30501 |
| + TF-IDF чатов Radiant и Dire | 0.31554 |
| + статистики золота и опыта, модель с `lbfgs` | 0.40066 |
| + общий линейный тренд | 0.40174 |
| + агрегации по временным окнам | **0.40239** |

Таблица показывает результаты последовательных этапов. Между этапами менялись в том числе фильтрация матчей и настройки модели.

На отдельном OOT-разбиении дополнительные признаки из пункта 6.4 подняли Gini с **0.41982 до 0.42112**. В эксперименте 6.5 на более поздней контрольной части жадный отбор исключил шесть столбцов общего тренда. Gini составил **0.41926** для отобранных групп и **0.41908** для полной модели. Эти оценки относятся к своим разбиениям.

### Данные

Скачай файлы из соревнования Kaggle по ссылке в разделе 1.1 [базового ноутбука](notebooks/homework-practice-03-base.ipynb) и размести их в `data/` под исходными именами.

- `matches_df_train.csv` и `matches_df_test.csv`
- `player_df.csv` и `Constants.Heroes.csv`
- `dota_adv.csv` и `game_chat.csv`

Данные и результаты обучения исключены из Git. В этой работе `player_df.csv` и `best_pipeline.joblib` превышают лимит обычного файла GitHub. При переносе в отдельный репозиторий достаточно скопировать `notebooks/`, `scripts/`, `data/.gitkeep`, `requirements.txt`, `README.md` и `.gitignore`. [Лимиты GitHub](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)

### Запуск

Пример для macOS/Linux с Python 3.14 из корня репозитория:

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m nltk.downloader wordnet
python -m ipykernel install --user --name dota-features --display-name "Python (Dota 2 features)"
python scripts/run_notebooks.py --kernel dota-features
```

Скрипт создаёт отдельную папку `artifacts/run-*/` и запускает в ней сначала базовый, затем продвинутый ноутбук. Это даёт ноутбукам доступ к CSV по относительным путям. Базовый ноутбук сохраняет четыре файла `.joblib`, которые затем читает продвинутый. Оптимизация на полном датасете может занять несколько часов.

Для запуска по ячейкам выполни `python scripts/run_notebooks.py --prepare-only`. Команда выведет абсолютный путь рабочей папки. Открой ноутбуки в Jupyter или PyCharm с этим рабочим каталогом. В интерактивном Jupyter рабочий каталог ядра также можно задать командой `%cd <путь из вывода>` перед запуском остальных ячеек каждого ноутбука.

### Выходные файлы

В рабочей папке остаются выполненные копии `*.executed.ipynb`, артефакты базовой модели и `submission.csv` с прогнозом основной сборки. `submission_64.csv` содержит прогноз модели с дополнительными признаками. Формат обеих таблиц — `ID,VALUE`, где `VALUE` — вероятность победы Radiant.

Для GPU-эксперимента подключи данные на Kaggle, включи GPU и вставь [скрипт бенчмарка](scripts/kaggle_gpu_benchmark_cell.py) целиком в ячейку после загрузки исходных DataFrame. cuML используется только в этом эксперименте.
